## Частина 2

### R1. `GET /api/health/abc`

- Прогноз: Router не найдёт подходящий маршрут и вернёт ошибку 404, потому что вместо числа переданы буквы.
- Факт:Получила статус 404 Not Found и JSON с кодом ошибки not_found.
- Хто вирішив і чому:Router. В регулярном выражении (\d+) разрешены только цифры, поэтому abc не соответствует маршруту /api/health/{id}.

### R2. Чому `helpers/routes.php` не можна додати в `autoload.files`?
helpers/routes.php возвращает массив маршрутов через return.
Если добавить этот файл в autoload.files, Composer автоматически выполнит его, но возвращённый массив не будет сохранён в переменную $routes.
Поэтому Router подключает файл через require и присваивает результат переменной $routes, чтобы затем перебрать маршруты в foreach.

## Частина 3

### V1. `is_numeric()` і пароль `"123"` з правилом `min:8`
Прогноз: is_numeric("123") вернёт true, хотя "123" — это строка.
Факт: is_numeric("123") вернул true, а is_int("123") и is_float("123") вернули false.
Объяснение: is_numeric() считает строку "123" числовым значением. Если использовать эту функцию в Validator, правило min:8 может ошибочно сравнить число 123 с 8 и пропустить слишком короткий пароль.
Поэтому для строк мы проверяем количество символов через mb_strlen(), а для настоящих чисел используем is_int() и is_float().

### V2. `static::$rules` чи `self::$rules`?
Прогноз:вернет true.
Факт: После замены static::$rules на self::$rules неправильные данные (email = "abc", password = "123") прошли проверку. Метод вернул bool(true), а массив ошибок оказался пустым.
Объяснение: self:: обращается к свойству класса, в котором определён метод, то есть Validator. static:: использует позднее статическое связывание и позволяет получить правила дочернего класса AuthValidator.
Поэтому в методе validate() необходимо использовать static::$rules.

## Частина 4

### L1. Забутий `return`

- Прогноз:  PHP продолжит выполнение метода login(), даже если функция jsonError() уже отправила ошибку.
- Факт (тіло, що в БД): Postman вернул статус 401 Unauthorized. В теле ответа сначала появилась ошибка invalid_credentials, затем HTML-предупреждения headers already sent, а после них — JSON с токеном и данными пользователя. В базе данных токен пользователя admin@example.com был перезаписан, несмотря на неправильный пароль.
- Чому `jsonError()` не зупиняє метод і які є інші способи: jsonError() только формирует и отправляет ответ, но не завершает выполнение метода login(). Для остановки используется return;. Другие способы — exit; (завершает выполнение всего PHP-скрипта) или выбрасывание исключения через throw, если в приложении 

### L2. `requestBody()` без перевірки + запит без тіла

- Прогноз: PHP выдаст TypeError, потому что функция requestBody(): array должна возвращать массив, а при пустом теле запроса json_decode() возвращает null.
- Факт (і тіло, і статус): При отправке POST /api/login с пустым телом сервер вернул ошибку Fatal error: Uncaught TypeError: requestBody(): Return value must be of type array, null returned. Вместо JSON пришла HTML-страница с сообщением об ошибке и стеком вызовов. HTTP-статус в эксперименте не был зафиксирован.
- Чому:Мы временно убрали ?: [], поэтому requestBody() попыталась вернуть null вместо массива. PHP обнаружил несоответствие объявленному типу array и прервал выполнение программы до валидации. После эксперимента мы восстановили ?: [], чтобы при пустом теле возвращался массив [].

### L3. Чому погано відповідати по-різному на «немає email» і «невірний пароль»?
Если сервер будет возвращать разные сообщения для несуществующего email и неправильного пароля, злоумышленник сможет определить, какие пользователи зарегистрированы в системе. Если злоумышленник узнает, что определённый email зарегистрирован, он сможет сосредоточиться на подборе пароля к этой учётной записи.
